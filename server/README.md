# Сервер

Исходники не зависят от существующего хостинга. Для своего сервера нужны PostgreSQL, HTTPS-сертификат и опубликованная сборка API. Клиентам передается только адрес API; PostgreSQL должен быть доступен только локально.

API использует следующие переменные окружения:

| Переменная | Значение |
|---|---|
| SUPPORT_HOME | Каталог конфигурации с password.json |
| SUPPORT_POSTGRES | Строка подключения Npgsql; хранить только на сервере |
| SUPPORT_CERT / SUPPORT_KEY | Пути к PEM-сертификату и ключу |
| SUPPORT_BIND / SUPPORT_PORT | Адрес и HTTPS-порт, по умолчанию 0.0.0.0:8444 |
| SUPPORT_EMBED_URL | Локальный сервис модели, по умолчанию http://127.0.0.1:8766 |

`SupportDesk.Api --init-db` создает схему в выбранной базе. `SupportDesk.Api --set-password` читает общий пароль из стандартного ввода, сохраняет хеш и отзывает сессии. Не передавайте пароль через аргументы командной строки. Обычный запуск — `SupportDesk.Api`. Все команды должны получать одинаковые переменные подключения. В изолированной разработке допускается SUPPORT_DB с путем SQLite вместо PostgreSQL.

Шаблоны `supportdesk-api.service` и `supportdesk-embeddings.service` используют `/opt/cristalix-support`. Адаптируйте пути и права под свое развертывание. Строку подключения задайте в `server.env` с правами 0640 или строже, доступную только администратору и пользователю сервиса. API требует заранее созданного password.json. Настройте регулярные резервные копии PostgreSQL через pg_dump.

Для локального поиска по смыслу установите Python-зависимости из requirements.txt в виртуальное окружение. Укажите SUPPORT_MODEL_DIR и запустите download_model.py один раз. Скрипт сохраняет ревизию и SHA-256 загруженной модели. Затем запускайте embedding.py: обработка работает локально, порт 8766 остается на loopback. Модель — Xenova/paraphrase-multilingual-MiniLM-L12-v2, ONNX, CPU.

Сервер проверяет версии при изменении ответов, хранит сессии и индекс в PostgreSQL. Смена общего пароля отзывает доступ; ранее скопированные тексты отозвать нельзя. Настройку резервного копирования и восстановление нужно проверить на своем сервере до использования.
